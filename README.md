# pump-dump-hunter

小幣拉高崩盤專用極短線。2026-09-16 判決（崩盤日模式 196 事件/90 天，無事後偏差）：**C（5m 崩盤棒破低追空）PF 5.7 是主力**；F（1m 清算連鎖追空）PF 1.32、B（反彈力竭做空）PF 1.12 邊際薄，實盤 1%/筆收執行數據；A 無效、E 在無偏差母體下無效、D 樣本不足。實盤 `ENGINES=B,C,F`。純標準庫 Python，零依賴，架構沿用 crypto-screener。

## 流程
1. **scanner.py** — 多頭擁擠名單：資金費率 ≥0.1%、48h 漲幅 ≥100%、OI 24h ≥+50%、偏離 1h MA20 ≥40%，中三項以上。
2. **signals.py** — 三個進場引擎（5m K）：
   - **A 崩前**：頂背馳（新高但 MACD 柱轉弱）→ 跌破中樞下緣進空，止損中樞上緣。
   - **B 崩後**：1h 內跌 ≥30% 且爆量 → 等反彈 20–50% 力竭（收破前根低點）進空，止損反彈高點。
   - **C 延續**：單根 5m 跌 ≥15% 爆量 → 3 根內破該棒低點進空，止損回抽高點上方。
   - **D 崩後 V 反（多）**：崩盤 2 小時內，出現爆量長下影（下影 ≥50%）且收盤收回前根實體一半、低點在崩盤低 5% 內 → 進多，止損該棒低點下 1%。出場快：最長 2 小時、1.5R 起追蹤。
   - **E 拉升初期（多）**：5m 收盤爆量突破 3 日高 → 2 小時內回踩到突破位 +4% 以內且不假跌破 → 再轉強進多，止損回踩低點下 2%。最長持有 24 小時、1h 級別追蹤。做多要付資金費率，回測未計。
3. **risk.py** — 每筆風險 = 本金 × 2%，用止損距離反推數量；槓桿是結果不是輸入，上限 20x。
4. **backtest.py** — 統一出場：1R 出一半並移止損到成本，2R 後用近 3 根高點追蹤，最長持有 6 小時。三引擎獨立計算。
5. **main.py paper** — 每 30 分重掃名單，每分鐘檢查 5m 新棒，出訊號就在 testnet 下市價空單 + 止損單（自動適配單向/對沖模式）。

## 用法
```
export BINANCE_KEY=... BINANCE_SECRET=... USE_TESTNET=1
python main.py scan
python main.py backtest AINUSDT 30
python main.py sweep 30        # 掃描名單全部回測
python main.py paper
```

## 先做的事
- 跑 `sweep 90`，看三個引擎的 R 分布，砍掉 PF<1 的。
- 把 `RISK.slippage` 換成 gold-live 蒐集到的實測滑價；小幣建議先抓 0.5–1%。
- 掃描層要接歷史資料才能真正回測「名單」本身；目前 sweep 是用當下名單回看，會有生存者偏差。

## Zeabur 部署
- 用 GitHub repo 建立服務，root 有 Dockerfile 會自動辨識；入口是 `server.py`（狀態頁 + 背景迴圈）。
- **Volume** 掛到 `/data`（state.json 放這裡，重佈不丟）。
- **環境變數** 照 `.env.example` 填；先 `TRADE=0` 只看訊號，確認幾天後再開 `TRADE=1`（仍走 testnet），最後才 `USE_TESTNET=0` 換真 key + 子帳號。
- 網域開了之後 `/` 是狀態頁、`/api/state` 是 JSON、`/health` 給探針。
